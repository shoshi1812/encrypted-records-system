# מתחילים כאן: העלאה לאינטרנט, צעד אחר צעד

המדריך מסביר איך להעלות את השרת לאינטרנט, גם בלי ניסיון קודם.
שלושה שירותים נפרדים: **GitHub** (הקוד), **ספק PostgreSQL** (מסד הנתונים) ו-**Render** (השרת).

> **הערה על שמות כפתורים:** ממשקי GitHub, Render וספקי מסד הנתונים משתנים מעת לעת. לא ניתן היה לוודא את שמות הכפתורים המדויקים בממשק העדכני, ולכן המדריך מתאר **מה** צריך לעשות, ושמות כפתורים מופיעים רק כהכוונה כללית. אם כפתור נקרא אחרת, חפשי את הפעולה המתוארת.

---

> ## ⚠️ שתי אזהרות לפני שמתחילים
>
> **1. ENCRYPTION_KEY נוצר פעם אחת בלבד.** אם תשני אותו או תאבדי אותו, כל התוכן הקיים במסד לא יהיה ניתן לפענוח יותר. **אין דרך לשחזר.** שמרי אותו במקום בטוח (למשל מנהל סיסמאות), ואל תכניסי אותו ל-Git.
>
> **2. הרצת Seed מוחקת את כל הרשומות הקיימות.** הריצי אותו רק על מסד חדש או מסד הדגמה.

---

## חלק א: GitHub

1. **פתיחת חשבון:** היכנסי ל-github.com והירשמי (אם אין לך חשבון).
2. **יצירת Repository:** מהתפריט בפינה העליונה בחרי ביצירת repository חדש. תני לו שם (למשל `encrypted-records`), השאירי אותו ריק, בלי README.
3. **חילוץ ה-ZIP:** חלצי את קובץ ה-ZIP במחשב. ודאי שנוצרה תיקייה ובתוכה התיקייה `server`.
4. **העלאת הקבצים דרך הדפדפן:** בעמוד ה-repository בחרי באפשרות להעלות קבצים קיימים (upload files), וגררי לחלון את **התוכן** של התיקייה שחילצת, כך שהתיקייה `server` תהיה בשורש ה-repository. אשרי את ההעלאה (commit).
   - אל תעלי `node_modules` או קובץ `.env`. הם אינם ב-ZIP ממילא.
5. **בדיקה:** ודאי שבעמוד ה-repository רואים את התיקייה `server`, ובתוכה `package.json`, `package-lock.json`, `prisma` ו-`src`.

## חלק ב: מסד נתונים

המדריך משתמש ב-**Neon** (neon.tech) כדוגמה, שמציע PostgreSQL במסלול חינמי. כל ספק PostgreSQL מנוהל אחר יעבוד באותו אופן. **בדקי את תנאי המסלול החינמי ואת מגבלותיו נכון ליום הפריסה.**

1. **פתיחת חשבון:** הירשמי באתר הספק.
2. **יצירת Database:** צרי פרויקט חדש. בחרי PostgreSQL בגרסה 15 ומעלה, ואזור קרוב לאזור שבו תפעילי את השרת ב-Render.
3. **קבלת Connection String:** בלוח הבקרה של הפרויקט יש אזור פרטי חיבור (Connection details / Connect). העתיקי את כתובת החיבור. היא נראית בערך כך:
   ```
   postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require
   ```
   - **חשוב לגבי pooler:** ספקים רבים מציעים שתי כתובות: חיבור רגיל (ישיר) וחיבור דרך pooler (אצל Neon הכתובת של ה-pooler מכילה את המילה `-pooler`). **Prisma Migrate אינו עובד דרך pooler.** הפתרון הפשוט ביותר: השתמשי בכתובת **הישירה** (ללא pooler) בתור `DATABASE_URL`, ואז אין צורך ב-`DIRECT_URL` כלל.
   - אם בכל זאת תרצי להשתמש ב-pooler לשרת, הגדירי את כתובת ה-pooler ב-`DATABASE_URL`, את הכתובת הישירה ב-`DIRECT_URL`, והוסיפי ב-`prisma/schema.prisma` בתוך `datasource db` את השורה `directUrl = env("DIRECT_URL")`.
4. **שמירה בבטחה:** כתובת החיבור כוללת סיסמה. שמרי אותה במנהל סיסמאות, ולעולם אל תכניסי אותה ל-Git.
5. **חיבור השרת למסד והרצת המיגרציות מהמחשב שלך:** במסלול חינמי בדרך כלל אין גישת shell לשרת ב-Render, ולכן הדרך הפשוטה היא להריץ את המיגרציות (ואם רוצים, את ה-Seed) מהמחשב שלך, כשהמשתנה `DATABASE_URL` מצביע על המסד בענן:
   ```bash
   cd server
   npm install
   # ב-.env: DATABASE_URL = הכתובת מהספק, ו-ENCRYPTION_KEY = אותו מפתח שתגדירי ב-Render
   npx prisma migrate deploy     # יוצר את הטבלאות במסד בענן
   npx prisma db seed            # אופציונלי: נתוני הדגמה (מוחק את כל הרשומות!)
   ```
   > אם את מריצה Seed, ה-`ENCRYPTION_KEY` במחשב שלך **חייב להיות זהה** לזה שב-Render. אחרת השרת לא יוכל לפענח את רשומות הדוגמה.

## חלק ג: Render

1. **פתיחת חשבון:** הירשמי ב-render.com. הכי נוח להירשם עם חשבון ה-GitHub.
2. **חיבור GitHub:** אשרי ל-Render גישה ל-repository שיצרת בחלק א.
3. **יצירת Web Service:** בלוח הבקרה בחרי ביצירת שירות חדש מסוג Web Service.
4. **בחירת ה-Repository:** בחרי את ה-repository של הפרויקט.
5. **הגדרות השירות:**

   | הגדרה | ערך |
   |---|---|
   | Root Directory | `server` |
   | Runtime | Node |
   | Build Command | `npm ci --include=dev && npm run build` |
   | Start Command | `npm start` |
   | Health Check Path | `/api/health` |
   | Instance type | המסלול החינמי |

   ההגדרות האלה מופיעות גם בקובץ `render.yaml`. אם Render מציע ליצור שירות מתוך הקובץ (Blueprint), אפשר להשתמש בו במקום להזין ידנית.

6. **משתני סביבה:** בהגדרות השירות, באזור משתני הסביבה (Environment), הוסיפי:

   | משתנה | ערך |
   |---|---|
   | `DATABASE_URL` | כתובת החיבור מחלק ב |
   | `JWT_SECRET` | מחרוזת אקראית ארוכה. יצירה: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
   | `JWT_EXPIRES_IN` | `60m` |
   | `ENCRYPTION_KEY` | יצירה **פעם אחת**: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` |
   | `CLIENT_ORIGIN` | כתובת הקליינט הפרוס, עם `https://` **וללא סלאש בסוף**. עד שהקליינט פרוס אפשר לשים `http://localhost:5173` ולעדכן אחר כך |
   | `NODE_ENV` | `production` |
   | `NODE_VERSION` | `22` |

   את `PORT` **לא** מגדירים. Render קובע אותו בעצמו.

7. **הרצת המיגרציות:** אם עוד לא הרצת, הריצי `npx prisma migrate deploy` מהמחשב כמתואר בחלק ב, סעיף 5. המיגרציות אינן רצות בכל עליית שרת, וזה מכוון.
8. **Deploy:** צרי את השירות. Render יבנה ויפעיל אותו. אפשר לעקוב אחרי הלוג בזמן הבנייה.
9. **בדיקה שהשרת פעיל:** בסיום תקבלי כתובת בסגנון `https://<שם-השירות>.onrender.com`. פתחי `https://<שם-השירות>.onrender.com/api/health`. אמורה להופיע תשובה עם `"status":"ok"`.

> **הערה מעשית:** שרת במסלול החינמי נרדם אחרי זמן ללא פעילות, והבקשה הראשונה אחרי שינה איטית (עד דקה בערך). **פתחי את `/api/health` כמה דקות לפני ההדגמה למורה** כדי להעיר אותו.

## חלק ד: בדיקה מקצה לקצה

1. **`/api/health`** מחזיר `{"status":"ok", ...}`.
2. **`/api-docs`** נפתח ומציג את תשעת ה-endpoints.
3. **Login מתוך Swagger:** פתחי את `POST /api/auth/login`, לחצי על הכפתור שמאפשר לנסות (Try it out), הזיני אימייל וסיסמה של משתמש קיים (למשל משתמש ה-Seed) והריצי.
4. **קבלת JWT:** העתיקי את הערך של `accessToken` מהתשובה (בלי מרכאות).
5. **Authorize:** לחצי על הכפתור **Authorize** בראש העמוד, הדביקי את הטוקן ואשרי.
6. **קריאה ל-Endpoint מוגן:** הריצי את `GET /api/auth/me`. אמורים לחזור הפרטים שלך.
7. **הוספת רשומה:** הריצי את `POST /api/cipher-records` עם הדוגמה שמופיעה שם. שימי ב-`recipientEmail` את האימייל שלך או של משתמש קיים אחר. העתיקי את ה-`id` מהתשובה.
8. **שליפתה:** הריצי את `GET /api/cipher-records/{id}` עם ה-`id`. התוכן אמור לחזור קריא.

הדגמת ההרשאות (נדרשת מהמורה): התנתקי ב-Authorize והריצי קריאה מוגנת (401). התחברי כמשתמשת רגילה והריצי `GET /api/admin/users` (403). נסי `PUT` על רשומה שאינה שלך (403).

## חלק ה: תקלות נפוצות

| תקלה | סימן | פתרון |
|---|---|---|
| Build Failed | הבנייה ב-Render נכשלת | ודאי ש-Root Directory הוא `server`, שה-Build Command הוא `npm ci --include=dev && npm run build`, ושהקובץ `package-lock.json` נמצא ב-repository. קראי את השורות האחרונות בלוג הבנייה |
| `DATABASE_URL` שגוי | השרת נופל בעלייה, או שגיאת חיבור למסד | העתיקי שוב את הכתובת מהספק. ודאי שהיא כוללת `sslmode=require` אם הספק דורש, ושאין רווחים או מרכאות מיותרות |
| בעיית Prisma | שגיאה שהטבלאות אינן קיימות, או migrate נתקע | הריצי `npx prisma migrate deploy` מהמחשב מול המסד בענן. אם migrate נתקע או נכשל, כנראה שהכתובת היא של pooler: השתמשי בכתובת הישירה (חלק ב, סעיף 3) |
| `JWT_SECRET` חסר | בלוג: "הגדרות הסביבה אינן תקינות: JWT_SECRET חסר" | הוסיפי את המשתנה בהגדרות השירות ב-Render ופרסי מחדש |
| `ENCRYPTION_KEY` חסר או באורך שגוי | בלוג: "ENCRYPTION_KEY חייב להיות 32 בתים בדיוק" | צרי מפתח בפקודה שבחלק ג. **אם כבר יש רשומות במסד, אל תיצרי מפתח חדש**: השתמשי במפתח המקורי, אחרת התוכן הקיים יאבד |
| שגיאת CORS | בקונסול של הדפדפן: "blocked by CORS policy" | `CLIENT_ORIGIN` ב-Render חייב להיות בדיוק כתובת הקליינט, כולל `https://`, ללא סלאש בסוף. אחרי שינוי יש לפרוס מחדש |
| 401 | "נדרשת התחברות" | הטוקן חסר, הועתק עם מרכאות, או שפג תוקפו (60 דקות). התחברי מחדש. ב-Swagger: Authorize מחדש |
| 403 | "הפעולה מותרת למנהל בלבד" או "רק יוצר הרשומה רשאי לערוך אותה" | זו התנהגות תקינה: אין לך הרשאה לפעולה. התחברי עם המשתמש המתאים |
| Swagger לא נפתח | עמוד ריק ב-`/api-docs` | ודאי שהכתובת היא `/api-docs` (עם מקף). רענני בכוח. אם העמוד עדיין ריק, פתחי את הקונסול בדפדפן וחפשי שגיאת Content Security Policy |
| השרת לא עולה | Render מסמן את השירות כנכשל, או Health Check נכשל | קראי את הלוג: השרת מדפיס בדיוק איזה משתנה סביבה חסר. ודאי ש-Health Check Path הוא `/api/health` ושלא הגדרת `PORT` ידנית |
| 404 ברענון עמוד בקליינט | רענון ב-`/records/...` באתר הפרוס מחזיר 404 | זה בקליינט, לא בשרת: באתר הסטטי חובה להגדיר כלל rewrite שמפנה כל נתיב אל `/index.html` |
