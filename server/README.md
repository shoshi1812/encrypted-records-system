# שרת מערכת רשומות מוצפנות

שרת Node.js ל-API של המערכת. משתמשת רשומה יוצרת רשומת מידע רגיש ומשתפת אותה עם נמען אחד. **תוכן הרשומה נשמר במסד הנתונים מוצפן בלבד**, ולא כטקסט קריא.

## טכנולוגיות וגרסאות

| רכיב | גרסה |
|---|---|
| Node.js | 20 או 22 (פותח ונבדק על 22) |
| Express | 4.22 |
| TypeScript | 5.9, במצב strict |
| PostgreSQL | 15 ומעלה (נבדק על 16) |
| Prisma ORM + Prisma Migrate | 6.19 |
| Zod | 3.25 |
| jsonwebtoken | 9.0 |
| bcrypt | 6.0 |
| helmet / cors / express-rate-limit | 8.3 / 2.8 / 8.7 |
| swagger-ui-express | 5.0 |
| Vitest + supertest | 5.0 / 7.3 |

ההצפנה משתמשת במודול `crypto` המובנה של Node, ללא ספרייה חיצונית.

## מבנה התיקיות

```
server/
  prisma/          schema.prisma, migrations, seed.ts
  src/
    config/        טעינת משתני הסביבה ואימותם ב-Zod
    db/            Prisma Client יחיד
    routes/        הגדרת נתיבים בלבד
    controllers/   קריאת הבקשה, ולידציה, קריאה ל-service, החזרת סטטוס
    services/      כללי עסק, הרשאות, הצפנה ופענוח
    validation/    סכמות Zod
    middleware/    auth, requireAdmin, errorHandler, notFound, rateLimit
    types/         טיפוסי DTO
    errors/        AppError וקודי השגיאה
    crypto/        encryptText ו-decryptText
    docs/          openapi.json ורישום Swagger
    app.ts         בניית אפליקציית Express
    server.ts      האזנה ל-PORT
  tests/           בדיקות Vitest
```

כיוון התלויות: `routes → controllers → services → prisma`. ה-controller אינו ניגש ל-Prisma ואינו מצפין. ה-service אינו מכיר את Express.

## התקנה והרצה מקומית

דרישות: Node.js 20 ומעלה ו-PostgreSQL פעיל.

```bash
cd server
npm install
cp .env.example .env        # ולמלא את הערכים, ראי למטה
npm run prisma:migrate      # יוצר את הטבלאות
npm run prisma:seed         # נתוני הדגמה (מוחק את כל הרשומות!)
npm run dev                 # http://localhost:4000
```

- בדיקת חיות: http://localhost:4000/api/health
- Swagger: http://localhost:4000/api-docs

## משתני סביבה

כל המשתנים נבדקים ב-Zod בעליית השרת (`src/config/env.ts`). ערך חסר או שגוי מפיל את השרת מיד, עם הודעה ברורה.

| משתנה | תיאור |
|---|---|
| `DATABASE_URL` | כתובת החיבור ל-PostgreSQL |
| `DIRECT_URL` | אופציונלי. רק אם ספק המסד מחייב חיבור דרך pooler (ראי הערה ב-`.env.example`) |
| `JWT_SECRET` | סוד לחתימת הטוקנים. אין ערך ברירת מחדל בקוד |
| `JWT_EXPIRES_IN` | תוקף הטוקן, `60m` |
| `ENCRYPTION_KEY` | מפתח ההצפנה: 32 בתים בקידוד Base64 |
| `PORT` | פורט ההאזנה. בענן נקבע על ידי הספק |
| `CLIENT_ORIGIN` | כתובת הקליינט המורשית ב-CORS, ללא סלאש בסוף |
| `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` | המנהל שה-Seed יוצר |
| `SEED_USER_EMAIL`, `SEED_USER_PASSWORD` | המשתמש הרגיל שה-Seed יוצר |

יצירת מפתח הצפנה:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

> ⚠️ **אזהרה: ENCRYPTION_KEY נוצר פעם אחת.** שינוי או אובדן של המפתח פירושו אובדן בלתי הפיך של כל התוכן הקיים במסד. אין דרך לשחזר. יש לשמור אותו במקום בטוח, ולעולם לא ב-Git.

## Endpoints

המפרט המלא, עם דוגמאות, נמצא ב-Swagger (`/api-docs`) ובקובץ [FRONTEND-API-GUIDE.md](FRONTEND-API-GUIDE.md).

| # | Method | URL | תיאור | הרשאות |
|---|---|---|---|---|
| 1 | GET | `/api/health` | בדיקת חיות השרת | פתוח |
| 2 | POST | `/api/auth/register` | הרשמה, מחזיר טוקן | פתוח |
| 3 | POST | `/api/auth/login` | התחברות, מחזיר טוקן | פתוח |
| 4 | GET | `/api/auth/me` | פרטי המשתמש לפי הטוקן | מחובר |
| 5 | GET | `/api/cipher-records` | רשימה עם חיפוש, סינון, מיון ודפדוף | מחובר |
| 6 | POST | `/api/cipher-records` | יצירת רשומה | מחובר |
| 7 | GET | `/api/cipher-records/{id}` | פרטי רשומה, תוכן רק לשולח ולנמען | מחובר |
| 8 | PUT | `/api/cipher-records/{id}` | עריכת רשומה, כולל התוכן | בעלים בלבד |
| 9 | GET | `/api/admin/users` | רשימת כל המשתמשים | מנהל בלבד |

אין endpoint למחיקה בגרסה זו.

### 401, 403 ו-404

- **401**: אין טוקן, או שהטוקן פגום או שפג תוקפו.
- **403**: הפונה רשאי לראות שהרשומה קיימת, אך אינו רשאי לבצע את הפעולה (עריכה בידי מי שאינו הבעלים). וגם: משתמש רגיל שפונה ל-`/api/admin/users`.
- **404**: הרשומה אינה קיימת, או שהפונה אינו רשאי לדעת על קיומה (רשומה פרטית שאינו צד לה).

ההכרעה כולה ממומשת בפונקציה `resolveAccess` בקובץ `src/services/cipherRecord.service.ts`.

## מודל ההצפנה וגבולות ההגנה

- **מה מוצפן:** תוכן הרשומה בלבד. כותרת, תיאור, קטגוריה, חשיפה, תאריכים ואימיילים נשמרים גלויים.
- **איך:** AES-256-GCM בשרת (`src/crypto`). לכל הצפנה nonce אקראי חדש בן 12 בתים. תג האימות (16 בתים) משורשר לסוף ה-ciphertext, והכול נשמר כ-Base64 בעמודה `encryptedContent`, וה-nonce בעמודה `nonce`.
- **עריכת תוכן** היא הצפנה חדשה לכל דבר: nonce חדש ו-ciphertext חדש, שמחליפים את הקודמים יחד באותה פעולת update.
- **המפתח** נמצא במשתנה הסביבה `ENCRYPTION_KEY` בשרת, ולא במסד הנתונים ולא בקוד.
- **הקליינט אינו יודע שיש הצפנה.** הוא שולח ומקבל טקסט רגיל בשדה `content`. השדות `encryptedContent` ו-`nonce` לעולם אינם יוצאים מהשרת.

**מפני מה המערכת מגינה:** דליפה של מסד הנתונים. גיבוי שנגנב, דאמפ של המסד או גישת קריאה בלבד אליו חושפים ciphertext בלבד.

**מפני מה היא אינה מגינה:** מי שיש לו גישה לשרת או לחשבון הענן, שם נמצא המפתח. זהו הדפוס המקובל שנקרא Application-level encryption at rest.

**המנהל:** רואה את כל הרשומות ברשימה, אך השרת אינו מחזיר לו את התוכן של רשומה שאינו צד לה. זו החלטת מוצר שממומשת בשכבת ה-service, ולא מגבלה מתמטית.

**חיפוש:** פועל על הכותרת בלבד. אי אפשר לחפש בתוכן, כי הוא מוצפן במסד.

## Seed

`npm run prisma:seed` יוצר מנהל ומשתמש רגיל (סיסמאות ממשתני הסביבה) וחמש רשומות דוגמה: פרטית של המשתמש לעצמו, ציבורית, אחת מהמשתמש למנהל, אחת מהמנהל למשתמש, ואחת פרטית של המנהל שהמשתמש אינו צד לה (להדגמת 404).

> ⚠️ **ה-Seed מוחק את כל הרשומות במסד בכל הרצה.** הוא מיועד לפיתוח ולהדגמה בלבד. אין להריץ אותו על מסד עם נתונים אמיתיים.

הרצה חוזרת מניבה בדיוק את אותה תוצאה (מחיקת הרשומות, upsert של המשתמשים לפי email, יצירת הרשומות מחדש).

## בדיקות

הבדיקות רצות מול **מסד נתונים נפרד** ועם מפתח הצפנה נפרד, מתוך הקובץ `.env.test`:

```bash
cp .env.test.example .env.test   # ולמלא DATABASE_URL של מסד בדיקות ו-ENCRYPTION_KEY
npm test
```

המיגרציות רצות אוטומטית על מסד הבדיקות לפני ההרצה, והטבלאות מתנקות לפני כל בדיקה. `NODE_ENV=test` משבית את הגבלת ניסיונות ההתחברות, ובדיקת ה-429 מפעילה אותה במפורש בקובץ שלה.

הבדיקות מכסות את כל 13 בדיקות הגרעין שבמסמך 05, ובנוסף: יחידות ההצפנה, 400 מול 413, nonce שמשתנה בעריכת תוכן ונשאר כשהתוכן לא נשלח, שליפה ישירה מהמסד שמוכיחה שהתוכן אינו גלוי, חיפוש, סינון, מיון ודפדוף, ותקינות openapi.json.

## אבטחה

- סיסמאות ב-bcrypt (cost 10). `passwordHash` לעולם אינו מוחזר.
- JWT ל-60 דקות. זהות הפונה נלקחת מהטוקן בלבד, לעולם לא מגוף הבקשה.
- helmet, CORS לכתובת הקליינט בלבד, גוף בקשה עד 1mb.
- הגבלת ניסיונות על `/api/auth`: 20 בקשות ל-15 דקות.
- הודעת התחברות כללית, ללא רמז אם האימייל קיים.
- אין רישום ללוג של סיסמאות, טוקנים, מפתחות, ciphertext או תוכן.
